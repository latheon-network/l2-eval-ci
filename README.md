# l2-eval-ci

Evaluation runs for Latheon's L2 framework comparison. Testnet research only, not part of the protocol.

`cdk/`: replays the Latheon V5 pool and distribution-router transactions (deploys, deposits, withdrawals with real Groth16 proofs; recorded on a local EVM from the unchanged contracts in latheon-network/Latheon) through the zkEVM of [cdk-erigon](https://github.com/0xPolygon/cdk-erigon) and reports the zkEVM virtual counters (steps, arith, binary, memAlign, keccak, padding, poseidon, sha256) of each transaction against the batch limits of the fork. It uses cdk-erigon's own counter harness (`zk/tests/zk_counters_test.go`).

The sender key in `cdk/latheon-txs.json` is the public Hardhat/Anvil test account #9. It holds nothing anywhere.

Run: GitHub Actions, workflow `cdk-erigon counters` (on push or manually). Results: job log and the `latheon-counters` artifact.

`arbitrum/`: starts the official Arbitrum nitro-testnode (L1 + L2 + an L3 whose gas is paid in a custom ERC-20 fee token, 18 decimals) in GitHub Actions and runs the Latheon evaluation scenario (`arbitrum/l2-eval/eval.js`, same 18 transactions, real proofs) on the L3. Workflow `arbitrum L3 custom gas token`. Results are committed to the `results` branch.

`arbitrum/rehearsal/`: rehearsal of a Latheon test chain on a public testnet. Workflow `arbitrum L3 rehearsal on Arbitrum Sepolia` (manual only) deploys a test LTH token (repo `LatheonToken`, unchanged) and a constant fee token pricer on Arbitrum Sepolia, creates an L3 rollup with `@arbitrum/chain-sdk` (Rollup mode, gas token = test LTH), runs its nitro node inside the job, deposits test LTH through the chain's inbox, creates the token bridge, lowers the minimum base fee, runs the Latheon scenario, checks that batches reach Arbitrum Sepolia, then stops and returns the batch poster's leftover ETH. The chain ends with the job. Needs the repository secret `REHEARSAL_DEPLOYER_KEY` (a dedicated test wallet with Arbitrum Sepolia ETH); optional secret `ARB_SEPOLIA_RPC`. Generated keys never leave the job; public results go to the `results` branch.

`testnet/latheon/`: Latheon contracts for the test chain. `build.js` compiles them from latheon-network/Latheon at a pinned commit into `artifacts/latheon-testnet.json` (committed); `deploy.js` deploys PoseidonT3, both verifiers, the four native-coin V5 pools and the native-coin router (on the test chain LTH is the gas coin, so the pools take and pay it directly: no wrapper, no approve), and checks every link plus one real proof per verifier; `smoke.js` deposits through the router, withdraws with real proofs to a new empty address and checks the invariants. `bench/` compares the gas of this with a wrapper-based setup on a local chain. On the server: `testnet/latheon-cmd.sh deploy|smoke`. Workflow `latheon contracts for the test chain` (free, on push) rebuilds the artifacts, checks they are identical, and runs both scripts on a local chain; the testnet stack rehearsal also runs them on its chain.
