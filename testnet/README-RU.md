# Тестовая сеть Latheon на сервере

Комплект поднимает на одном сервере:
- узел L3 (Arbitrum Nitro) поверх Arbitrum Sepolia, газ в тестовом LTH;
- публичный RPC по HTTPS: `https://RPC_HOST`;
- обозреватель блоков Blockscout по HTTPS: `https://EXPLORER_HOST`.

Это тестовая сеть. Тестовый LTH к реальному токену отношения не имеет.

Вся процедура отрепетирована в GitHub Actions (workflow `testnet server stack (rehearsal)`): тот же `setup-server.sh`, тот же `deploy-chain.sh`, те же контейнеры. Отличия CI от сервера: самоподписанный сертификат вместо Let's Encrypt, без ожидания финальности и пакеты каждые 30 секунд.

## Что нужно заранее

1. Сервер: Ubuntu 24.04, 8 ядер, 16 ГБ памяти, от 150 ГБ диска, SSH-ключ.
2. Отдельный кошелёк деплоя примерно с 0,1 ETH в Arbitrum Sepolia (0,02 уйдёт адресу, который публикует пакеты).
3. Свой RPC Arbitrum Sepolia (Alchemy или Infura). Узел читает родительскую сеть постоянно, публичный RPC для этого ненадёжен.
4. Две DNS-записи типа A на IP сервера, например `rpc.testnet.latheon.xyz` и `explorer.testnet.latheon.xyz`. Их добавляют там, где управляется DNS домена latheon.xyz.

## Шаги

С ноутбука (PowerShell), подставив IP сервера:

```powershell
ssh -i "C:\Users\smirn\.ssh\latheon_server" root@IP_СЕРВЕРА
```

Дальше всё на сервере:

```bash
git clone https://github.com/latheon-network/l2-eval-ci.git
cd l2-eval-ci/testnet
./setup-server.sh
nano .env          # RPC_HOST, EXPLORER_HOST, PARENT_RPC
./deploy-chain.sh  # спросит ключ кошелька деплоя, ввод скрыт
```

`deploy-chain.sh`:
1. разворачивает в Arbitrum Sepolia тестовый LTH, контракт курса газового токена и контракты сети;
2. пишет конфигурацию узла и запускает все контейнеры;
3. ждёт, пока узел начнёт отвечать. Первый раз узел ждёт финальности блока с созданием сети, это до часа;
4. заводит 10 000 тестовых LTH в сеть на адрес деплоя, создаёт мост для других токенов, проверяет публикацию пакетов.

Скрипт можно перезапускать: готовые шаги пропускаются.

## Что хранить и чего не публиковать

- `chain/secret/` содержит ключи адреса публикации пакетов и валидатора и конфигурацию узла. Сделай резервную копию на ноутбук и никуда не выкладывай:
  ```powershell
  scp -i "C:\Users\smirn\.ssh\latheon_server" -r root@IP_СЕРВЕРА:/root/l2-eval-ci/testnet/chain/secret "C:\Users\smirn\Desktop\Latheon Network\testnet-secret-backup"
  ```
- `.env` содержит пароль базы и адрес RPC с ключом. Не публиковать.
- `chain/out/chain.json` хранит только публичные данные: адреса контрактов, chainId, хеши транзакций.

## Контракты Latheon в сети (неделя 2)

После `./deploy-chain.sh`, когда RPC сети отвечает и на кошельке деплоера есть LTH в самой сети (его туда кладёт шаг `fund`):

```bash
cd ~/l2-eval-ci/testnet
./latheon-cmd.sh deploy     # спросит ключ деплоера, ввод не отображается
./latheon-cmd.sh smoke      # проверка с настоящими доказательствами
```

`deploy` разворачивает WLTH, Poseidon, верификаторы вывода и раскрытия, четыре пула V5 (100 / 50 / 10 / 1) и роутер. Потом проверяет каждую связь: токен, верификатор и номинал каждого пула, `zeros(8)` (ошибочную привязку Poseidon), пулы и лимиты роутера, и по одному настоящему доказательству на оба верификатора. Повторный запуск ничего не разворачивает заново, а берёт уже развёрнутое.

`smoke` оборачивает 11 LTH, вносит их через роутер двумя нотами (10 и 1), выводит обе одним `withdrawMany` с настоящими доказательствами, разворачивает обратно и проверяет, что у роутера ничего не осталось, а WLTH полностью обеспечен. В конце проверяет доказательство раскрытия.

Почему WLTH: в нашей сети LTH — родная монета, ею платят газ. Пулы V5 и роутер работают с токеном ERC-20, поэтому они стоят на обёртке WLTH: 1 WLTH = 1 LTH, `deposit` оборачивает, `withdraw` разворачивает (как WETH). Сами пулы и роутер те же, что в трёх тестнетах, без изменений.

Результат для демо: `latheon/out/latheon-deployments.json` (запись в формате `demo/deployments.json`). Файлы схем скачиваются по коммиту Latheon и сверяются по хешам; тестовые ноты остаются в `latheon/secret/`.

## Обслуживание

```bash
cd ~/l2-eval-ci/testnet
docker compose ps                 # состояние
docker compose logs -f --tail 50 nitro
./chain-cmd.sh batches            # пакеты доходят до Arbitrum Sepolia?
docker compose restart nitro
```

Адресу публикации пакетов нужен ETH в Arbitrum Sepolia. Адрес лежит в `chain/out/chain.json` (`batchPoster`), баланс видно на sepolia.arbiscan.io. Пополнять, когда остаётся меньше 0,005 ETH.

## Чего пока нет

- Валидатор выключен. Пока его нет, выводы из сети обратно в Arbitrum Sepolia не подтверждаются. Депозиты в сеть работают. Включение валидатора — отдельная задача.
- Blockscout: последняя публичная версия образов 9.0.2 (бэкенд) и v2.3.1 (интерфейс). Внутренние транзакции не отслеживаются, потому что отладочные методы узла закрыты снаружи.
- Ограничения частоты запросов к RPC нет. Тело запроса ограничено 1 МБ.
- Контракты Latheon разворачиваются командой `./latheon-cmd.sh deploy` (см. выше); в демо сеть ещё не подключена: нужна поддержка WLTH (обернуть перед депозитом, развернуть после вывода).
- Кран (faucet) для новых адресов ещё не сделан: свежему адресу нужен немного LTH на газ, иначе он не сможет развернуть полученный WLTH.
